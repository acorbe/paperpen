Working the queue

Deciding which paper to work on is not repository work. The registry, the shelf and the queue already stand above every repository, and these are the commands that read them.

paperpen queue                   # every open note, every paper, oldest first
paperpen queue --json            # the same, on stdout, with nothing else on it
paperpen queue --unclassified    # the ones left on AUTO, which is the triage
paperpen queue --paper X --older-than 14
paperpen next                    # what to do first, and the command that does it
paperpen next --all --json       # the whole list, in order

What next answers

Four kinds, never a fifth:

classifyDelivered notes have no class. The class decides who acts on a note, so this is the cheapest thing that unblocks the rest.
workA round is still open. The answer names the round's NOTES.md and how old it is.
buildThe source has moved past the build the reader is showing.
finishA reading is open and unsent. Reported, not urged: whether a round is finished is a judgment about a paper, not arithmetic about notes.

Neither command writes anything, which is what makes them safe to give to something that has no business editing a manuscript.

Acting on one note

Every row carries what is needed without opening the paper first: the source line, the sentence the note sits on, its age, and for a handwritten note the path to its picture.

{
  "id": "2026-04-02-07",
  "paper": "my-manuscript",
  "tag": "AUTO",
  "source": "sec_results.tex:41",
  "anchor": "Above the knee the 48 cells agree closely; below it they scatter.",
  "ink": "~/papers/manuscript/review/2026-04-02/ink/2026-04-02-07.png",
  "age": 6,
  "handwritten": true
}

There is no OCR anywhere in this, so a handwritten note is read by whoever picks it up, which may be something with no browser, hence the path.

Two scopes, not two processes

The useful split is not how many things are running, it is what each of them can reach.

  • Above the repositories: the queue, the triage, the ordering, and closing a note. These go through the registry and work from any directory. Nothing here needs a paper's source.
  • Inside one repository: reading review/<date>/NOTES.md, changing the LaTeX, rebuilding, committing. One build, one history, one set of co-authors; a mistake reaches one paper.
Check which shelf is in force. A .paperpen/papers.json in the current directory wins over the global registry. Anything running in such a directory is looking at a different shelf, silently. paperpen where says which.

What a paper's repository should say

Whoever works in the paper's own repository, a person or otherwise, needs to know three things, and they belong in that repository rather than in somebody's head:

  1. review/<date>/NOTES.md is what to act on. Line numbers are from the build the note was made on and drift as the source is edited; the quoted sentence is what to search for.
  2. notes.json is the record; NOTES.md is generated from it, so it is never hand-edited.
  3. A note is closed with paperpen resolve, with what was done, so the next reading shows what happened to the last one.
