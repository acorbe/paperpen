The tablet, over the network

The reader is worth having on the tablet, which means the server has to leave the machine it runs on. That is one flag, and it is closed behind a login unless you choose otherwise.

paperpen onboard             # the login, the certificate and a first paper, once
paperpen lan                 # choose the login again
paperpen tls                 # a certificate for this machine
paperpen serve --lan         # every interface, over https, behind the login

serve --lan prints what the tablet needs:

The login

Onboarding and paperpen lan ask how the reader on the network lets people in:

  1. A password and six digits from an authenticator app. Recommended, and the default.
  2. A password only.
  3. No login. Anyone who can reach the address can read your papers and notes, change their sources and download all of it. Fair at home, on a network that is yours; wrong on conference or campus wifi. It is confirmed by typing no login, and serve --lan warns about it every time it starts. paperpen lan --no-login chooses it directly, and paperpen lan turns a login back on.

Nothing is ever served to the network unlocked by default: until one of the three is chosen, serve --lan asks.

  • The password is hashed with scrypt and kept in ~/.config/paperpen/auth.json, mode 600, and deliberately not papers.json, which is the file meant to be handed around.
  • paperpen lan offers a second factor: a standard TOTP secret any authenticator app will take, shown as a QR code to scan.
  • A wrong password and a wrong code give the same answer, and a failure costs a second.
  • Whatever the login, the server refuses a write sent by another site's page, and on loopback answers only to its own name, because any page open in your browser can send requests to this machine.

The certificate

paperpen tls makes a self-signed certificate for this machine and prints its fingerprint and both honest ways to use it:

  • Install it on the tablet (the file is ~/.config/paperpen/tls/cert.pem) and the browser stops complaining. On iOS that is Settings → General → VPN & Device Management, then Certificate Trust Settings.
  • Or accept the warning once, after checking the fingerprint against what the terminal printed. That is a real check, not a formality: it is what the warning is asking you to do.
The address is in the certificate, as an address. A certificate naming only a hostname has not been accepted by a browser since 2017, so the LAN address goes in as an IP subject alternative name. If the machine's address changes, serve --lan says so and paperpen tls --renew makes a new one. The certificate is good for 397 days, because Apple refuses anything longer.

Taking the state with you

The rounds are the one thing here that cannot be made again, and the tablet has no terminal. take the state in the shelf header is the whole of it as one file:

paperpen bundle                  # everything: the registry and every round
paperpen bundle my-manuscript    # one paper, with its manifest
paperpen bundle --ink            # include the rendered handwriting

The same two are /state.tar.gz and /paper/<id>/state.tar.gz in a browser. The rendered ink is left out by default: it comes back from the strokes and is most of the bytes.

A paper that carries its own history

With record: repo, a finished round leaves a manifest beside itself in the paper's repository:

<paper>/review/
  paperpen.json          which paper this is, how it is read, which rounds exist
  2026-04-02/            NOTES.md, notes.json, ink/

That is enough to rebuild the shelf entry from a clone, which is what adopt does, so a paper can move between machines, or be picked up by whoever has the repository:

paperpen adopt git@example.org:group/manuscript.git
paperpen adopt ~/papers/manuscript
paperpen sync                    # pull every paper's repo, re-read the rounds
